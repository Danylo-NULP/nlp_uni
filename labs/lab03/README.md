# Lab 3: Lemmatization & POS Tagging

### 1. Напрям
**A (Класифікація текстів)**. Задача NLI (Entailment, Contradiction, Neutral).

### 2. Інструмент
Використано **spaCy** (`en_core_web_sm`), оскільки датасет англомовний. Інструмент успішно впорався з омонімами (наприклад, "saw" як дієслово і як іменник) у тестових `ling_edge_cases.jsonl`.

### 3. Базлайни
* **Baseline 1:** `TF-IDF` + `LogisticRegression` на звичайному очищеному тексті.
* **Baseline 2:** `TF-IDF` + `LogisticRegression` на лематизованому тексті.

### 4. Цифри "До / Після"
* **Baseline 1 (Raw):** Acc = `0.4267`, F1 = `0.4269`
* **Baseline 2 (Lemma):** Acc = `0.4100`, F1 = `0.4088`

### 5. Висновок
Для задачі виявлення логічного зв'язку (NLI) використання суворої лематизації **недоцільне**. Втрата граматичних форм (часу, числа) призводить до втрати контексту, що знижує точність класифікатора на ~1.5%. POS-теги можуть бути корисними хіба що як додаткові структурні фічі, але не як заміна основного тексту.
