# Лабораторна робота №14 — Stateful Flow Orchestration

### 1. Опис Use Case
Метою роботи є розробка оркестрованого пайплайну (Stateful Flow) для обробки та структурування описів фотографій (Image Captions) з датасету SNLI.
Система приймає сирий текст, самостійно визначає його категорію (люди, тварини, пейзажі), витягує дані за жорсткою JSON-схемою, перевіряє їх на галюцинації та безпечно експортує результат у зовнішні системи.

### 2. Етапи Flow (Оркестрація)
Пайплайн працює з єдиним об'єктом стану (`FlowState`) і проходить через 6 обов'язкових кроків:
1. **Ingest:** Приймання тексту, нормалізація, генерація унікального `case_id`.
2. **Route:** Локальна LLM класифікує сцену та обирає відповідну JSON-схему екстракції.
3. **Execute:** Локальна LLM витягує сутності строго за обраною схемою.
4. **Validate:** Python-бібліотека `jsonschema` перевіряє структуру та відловлює пропущені обов'язкові поля (галюцинації/втрати).
5. **Fallback:** Безпечний збій (Safe Failure). Якщо валідація провалена, система маркує запис як *Needs Manual Review*, зберігаючи часткові дані.
6. **Export:** Формування фінального, передбачуваного JSON для збереження у БД, незалежно від статусу (успіх чи помилка).

### 3. Технічний стек та Модель
Замість платних API використано локальну 오픈сорс-модель **Llama-3-8B-Instruct** (у 4-бітному квантуванні через `unsloth` та `bitsandbytes`). Це забезпечує повну незалежність пайплайну та можливість роботи на GPU (T4 у Colab). Всі виклики моделі налаштовані на жорсткий JSON-вихід (`do_sample=False`, `temperature=0`).

### 4. Метрики та Результати (на 10 Test Cases)
* **Flow completion rate:** ~70% (завершили експорт з даними).
* **Fallback activation rate:** 30% (Спрацьовує на занадто коротких текстах, таких як "A person.", або коли LLM помиляється з типами даних).
* **Safe Failure:** 100% успішне відловлювання фатальних помилок. Жоден збій (наприклад, симуляція `DROP TABLE`) не призвів до падіння всієї програми — система стабільно повертала задокументований експорт із логом помилки.

### 5. Головний висновок
Перехід від незалежних агентів до Stateful Flow дозволяє створити production-ready систему. Завдяки ізоляції стану та чіткому етапу `Fallback`, система стала стійкою до природних недоліків великих мовних моделей (галюцинацій та помилок форматування), гарантуючи стабільний контракт даних для кінцевого споживача.
