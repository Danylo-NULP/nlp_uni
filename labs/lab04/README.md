# Лабораторна робота №4 — Модуль правилового витягу інформації (Rule-based IE)

### 1. Витягнуті типи полів
Враховуючи специфіку англомовного корпусу коротких описів зображень датасету SNLI, для витягу структурованої інформації було обрано три типи сутностей:
1. **QUANTITY (Кількість):** Витяг числових значень (`3`), текстових числівників (`five`) та квантифікаторів множини (`group`), що нормалізуються у відповідні цифрові рядки або токен `"many"`.
2. **COLOR (Колір):** Видобуток назв кольорів елементів одягу та об'єктів з нормалізацією відтінків до базових спектрів (`navy` -> `blue`, `dark` -> `black`).
3. **LOCATION (Локація):** Класифікація типів сцен за просторовими зонами (`road` -> `street`, `ocean` -> `water_area`, `kitchen` -> `indoor`).

### 2. Використані правила та словники
Реалізований у модулі `src/ie_rules.py` детермінований підхід базується на концепції **Precision-first** (мінімізація хибних спрацювань) і використовує:
* **Вбудовані словники нормалізації:** Словники `COLORS_DICT`, `LOCATIONS_DICT` та `TEXT_NUMBERS` інтегровані безпосередньо в код для забезпечення кросплатформеної стабільності в Colab без завантаження зовнішніх JSON-файлів.
* **Регулярні вирази з контролем меж слів:** Використання метасимволів `\b` запобігає помилковому витягу токенів із середини довших слів (наприклад, виключено запуск `one` всередині слова `Someone`).
* **Жорсткі правила-запобіжники (Lookahead & Lookbehind):**
  * Для `QUANTITY`: Конструкція `(?<![-#])(?<!number\s)` блокує номери гравців та відсотки (`100%`).
  * Для `COLOR` та `LOCATION`: Негативний перегляд вперед `(?!...)` ігнорує відомі ідіоми (`black eye`, `out of the blue`), прикметники (`street vendor`) та назви спорту (`water polo`).
  * **Фільтрація за регістром (Capitalization check):** Слова з великої літери всередині речення розпізнаються як власні назви (`Red Cross`, `Park Avenue`) та автоматично відкидаються.

### 4. Топ-5 Edge Cases та аналіз False Positives у корпусі
Під час тестування модуля на крайових випадках (`tests/ie_edge_cases.jsonl`) було зафіксовано два специфічні прориви нашої регулярної системи захисту:
1. `A one-way street.` — Витягнуто: `street [LOCATION]`. *Аналіз:* Наше правило успішно заблокувало числівник `one` через дефіс, проте слово `street` було вилучено. В межах даної фрази це прийнятно, оскільки дія дійсно відбувається на вулиці.
2. `A white-collar worker.` — Витягнуто: `white [COLOR]`. *Аналіз:* Хибне спрацювання (False Positive). Ідіома соціологічного терміну "білі комірці" пробила фільтр, оскільки lookahead був налаштований лише на `collar`, але не врахував дефіс `white-collar`.
3. `Catch-22 is a great book.` — Результат: `Нічого` (Успішне відсікання дефісу та назви книги).
4. `He has a black eye.` — Результат: `Нічого` (Успішне блокування ідіоми синця завдяки lookahead на `eye`).
5. `Playing water polo.` —  Результат: `Нічого` (Успішно заблоковано назву спорту за допомогою lookahead на `polo`).

### 5. Що планується покращити в наступних лабах
Для усунення помилок типу `white-collar` (де слово є частиною складеного прикметника) регулярних виразів недостатньо. У наступних роботах планується інтегрувати лінгвістичні фічі з **Лабораторної роботи №3 (POS-теги)**. Модуль буде модифіковано так, щоб сутності `COLOR` та `LOCATION` витягувалися лише у випадку, якщо морфологічний аналізатор присвоїв токену тег іменника (`NOUN`) або окремого прикметника (`ADJ`), повністю відсікаючи дефісні сполучення зі статусом складних часток.
