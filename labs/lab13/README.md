# Лабораторна робота №13 — Multi-Agent Crew

### 1. Опис Use Case
Метою роботи є створення **Multi-Agent Crew** для безпечного та структурованого витягування метаданих з описів фотографій (датасет SNLI). На відміну від одного агента, тут застосовано розподіл ролей, щоб мінімізувати галюцинації (вигадування кольорів чи одягу) та забезпечити динамічну обробку різних типів сцен.

### 2. Архітектура та Ролі Агентів
Реалізовано пайплайн із 4 компонентів:
1. **Triager (Маршрутизатор):** Аналізує текст і визначає фокус сцени (`human_focus`, `animal_focus`, `scenery_focus`), формуючи динамічну схему для наступного кроку.
2. **Extractor (Екстрактор):** Виконує безпосереднє витягування даних (JSON) згідно із заданим маршрутом.
3. **Reviewer (Контролер):** Звіряє отриманий JSON з оригінальним текстом. Блокує результат, якщо знаходить галюцинації або логічні суперечності.
4. **Fallback (Рятувальник):** Забезпечує механізм безпечного збою (*Safe Failure*). Якщо Reviewer забракував екстракцію, кейс маркується для ручної перевірки, щоб "брудні" дані не потрапили в БД.

### 3. Оцінка (Baseline vs Multi-Agent Crew)
Під час тестування на 10 кейсах Baseline-модель (працюючи "наосліп") часто намагалася застосувати єдину схему до всіх текстів. Наприклад, для пейзажів вона могла вигадати "одяг" або дії. 

**Переваги Crew:**
* **Динамічність:** Triager успішно розкидає задачі на різні схеми.
* **Надійність:** Reviewer ловить галюцинації та провокації (наприклад, спроби Prompt Injection).
* **Safe Failure:** Проблемні кейси не зберігаються "як є", а свідомо направляються на ручне рев'ю.

### 4. Головний висновок
Архітектура Multi-Agent Crew — це індустріальний стандарт для побудови надійних NLP-пайплайнів. Делегування валідації окремому агенту (Reviewer) є найефективнішим способом боротьби з притаманними LLM галюцинаціями, особливо при роботі з короткими текстами, такими як Image Captions.
