# Лабораторна робота №6 — TF-IDF + Logistic Baseline

### 1. Напрям проєкту
**Напрям А (Класифікація текстів).** Задача Natural Language Inference (NLI).

### 2. Підзадача класифікації
Багатокласова класифікація логічних відношень між двома реченнями (Premise та Hypothesis). Тексти об'єднані через токен `[SEP]`. Цільова змінна має три класи: `entailment` (слідування), `contradiction` (суперечність) та `neutral` (нейтральність).

### 3. Baseline-варіанти
Для уникнення витоку даних (data leakage) класифікатори були загорнуті у `sklearn.pipeline.Pipeline`, де `fit` виконувався суворо на тренувальній вибірці. 
* **Baseline 1:** TF-IDF `ngram_range=(1,1)` + Logistic Regression.
* **Baseline 2:** TF-IDF `ngram_range=(1,2)` + Logistic Regression.

### 4. Основні цифри (Метрики на Test Set)
* **Baseline 1 (Unigrams):** Accuracy = 0.4000, Macro-F1 = 0.3999
* **Baseline 2 (Bigrams):** Accuracy = 0.3867, Macro-F1 = 0.3862
* *Примітка:* Додавання біграм не покращило, а навіть дещо погіршило результат. Це пов'язано з тим, що TF-IDF матриця стала більш розрідженою (sparse), а локальні біграми не допомогли встановити глобальний логічний зв'язок між реченнями.

### 5. Error Analysis та подальші кроки
Ручний аналіз помилок (Error Analysis) виявив фундаментальні недоліки підходу Bag-of-Words (TF-IDF) для задачі NLI:
1. **Лексичне перекриття (Lexical Overlap):** Модель масово хибить, прогнозуючи `entailment`, якщо об'єкти (наприклад, "A little girl" або "A person") збігаються, повністю ігноруючи дії, які суперечать одна одній ("swimming" vs "leaping into the air").
2. **Сліпота до контексту:** Модель не розуміє синонімів та антонімів, оскільки аналізує лише статистичну частоту токенів.

**Що будемо фіксити далі:** Лінійні моделі вичерпали свій потенціал для цієї задачі. У наступних лабораторних необхідно відмовитися від TF-IDF на користь векторних семантичних моделей (Dense Embeddings) або архітектур на базі Transformer (наприклад, BERT / Sentence-BERT), які здатні аналізувати послідовність слів та контекстуальні зв'язки.
